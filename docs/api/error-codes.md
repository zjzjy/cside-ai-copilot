# API 错误码

## 通用错误码

| code | message | 说明 |
|:----:|---------|------|
| 0 | success | 成功 |
| 1001 | 参数校验失败 | 请求参数不合法，具体原因见 message |
| 1002 | 未登录或 Token 过期 | 需重新登录 |
| 1003 | 无权限 | 当前角色不能执行此操作 |
| 9999 | 系统未知错误 | 需查看后端日志 |

## 业务错误码

| code | message | 说明 |
|:----:|---------|------|
| 2001 | LLM 调用失败 | 模型 API 不可用或超时 |
| 2002 | LLM 返回格式异常 | 五步 JSON 解析或校验失败 |
| 2003 | RAG 检索超时 | 向量库或 Embedding 服务异常 |
| 3001 | 对话不存在 | conversation_id 无效 |
| 3002 | 客户消息为空 | customer_message 为空或纯表情 |
| 3003 | 消息超出字数限制 | 超过 500 字符 |
| 4001 | 收藏内容为空 | content 字段为空 |
| 4002 | 步骤类型无效 | step_type 不在 1-5 或 full 范围内 |
| 5001 | 品牌不存在 | brand_id 对应的品牌记录未找到 |
| 5101 | 店铺不存在 | store_id 对应的店铺记录未找到 |

## 新增规则

- 后端遇到新错误场景时，在本文件末尾追加，不要修改已有 code 编号
- 新增后群里通知前端，确保两边对错误码的理解一致

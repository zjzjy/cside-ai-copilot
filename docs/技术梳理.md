# CSide 项目技术梳理

> **文档定位**：这份文档描述项目的**设计全貌**，同时包含「V1 已实现」与「迭代二规划」两部分。
> 已交付范围与实现状态以 [README 功能状态表](../README.md#五功能与交付状态) 为准；本次迭代安排见 [ROADMAP.md](ROADMAP.md)。
> 标注说明：正文中 Agent Orchestrator 与 8 个工具、多模态输入、11 张表、评估与监控为**迭代二设计**，V1 已实现的是单 Agent 五步生成 + 三级知识库混合检索。

## 一、产品定位

**CSide 是一个面向电商代运营场景的浏览器侧边栏 AI 客服副驾驶。** 客服在淘宝/京东/拼多多后台工作时，选中客户消息按快捷键，AI 自动生成五步结构化回复话术（意图→策略→话术→钩子→收尾），客服可逐步修改、级联重生成、一键复制发送。

- **给谁用**：代运营客服，一人同时管多品牌（vivo/OPPO/小米/华为）、多平台（淘宝/京东/拼多多/抖音）、多店铺
- **核心痛点**：质量鸿沟（资深vs新人话术差距大）、效率瓶颈（大促同时接待20人）、经验流失（年流失25-40%）
- **产品形态**：Chrome Side Panel 侧边栏（主要操作界面）+ 管理后台 SPA + Spring Boot 后端

## 二、核心业务流程

### 1. 话术生成主链路

```
客服选中客户消息 → Ctrl+Shift+F → POST /api/v1/generate
  → JWT认证 → 品牌/店铺解析 → Agent工具编排 → RAG多路检索
  → Prompt构建 → LLM生成五步JSON → 校验 → 返回前端展示
```

### 2. Agent Orchestrator + 8工具

单模型统一承担三个角色：意图分类 → 工具编排决策 → 五步话术生成。8个只读工具的调用由Agent根据客户意图自主决定，不做硬编码路由。

```
工具集：
  search_product     → 商品参数/价格/库存（pgvector语义 + SKU精确匹配）
  search_policy      → 退货/保修/平台政策（BM25+向量混合检索）
  search_faq         → FAQ语料语义检索
  search_script      → 历史优质话术模板检索
  search_image       → CLIP以图搜商品（Jina CLIP v2, POST /api/v1/search/image）
  parse_url          → 商品链接解析 → ERP API查询商品信息
  understand_image   → 多模态LLM直接理解订单截图/故障照片
  understand_video   → 视频关键帧提取 + OCR + ASR → 转文字
```

**选型决策**：用30条客服消息对比评测单Agent vs Agent+Tool Router。参考ASA论文（LLM在>80%情况下知道该调工具却不触发调用），设置决策门槛：Tool调用准确率<80%则降级为单Agent方案。

**为什么是Orchestrator而非ReAct**：客服场景核心是"在正确知识上生成正确话术"，不是多步推理。ReAct的Think-Act-Observe循环延迟高，且客服场景不需要多轮工具交互。

### 3. 多模态输入管线

四种输入类型，统一路由到不同的处理管线，最终合并为结构化上下文注入LLM：

**图片输入（双路并行）：**

| 路线     | 技术         | 用途                                | 实现                                              |
| -------- | ------------ | ----------------------------------- | ------------------------------------------------- |
| CLIP匹配 | Jina CLIP v2 | 识别客户发的商品图片，匹配到具体SKU | 图片→768维CLIP向量→pgvector HNSW→Top-K SKU结果 |
| 内容理解 | 多模态LLM    | 理解订单截图、故障照片等场景图片    | 图片→多模态LLM直接返回文字描述→合并到消息文本   |

CLIP向量库与文字向量库分离：`product_images`表独立存储768维向量（文字为1024维），不同向量空间不可混合检索。HNSW索引加速ANN检索，支持按品牌过滤。

**视频输入：** 关键帧提取 → 帧图像OCR + 音轨ASR语音识别 → 转文字 → 进入标准五步生成流程。不直接对视频做语义理解（计算成本过高）。

**链接输入：** URL解析器提取平台域名+商品ID → 调用ERP API查询商品信息（SKU/参数/价格/库存）→ 注入LLM上下文。

### 4. RAG 混合检索

- **多路并行**：商品库 + 政策库 + FAQ库 + 话术模板库
- **混合打分**：`最终分数 = 0.75 × 归一化BM25 + 0.20 × 向量余弦 + 层级boost`（店铺层+0.05, 品牌层+0.03, 通用层+0.00）
- **中文BM25**：自实现，汉字按1-gram+2-gram组合分词（"耳机不响"→["耳","耳机","机","机不","不","不响","响"]），英文/数字按空格切分。BM25参数k1=1.2, b=0.75
- **Embedding增强**：query前拼接指令前缀 `"为这个句子生成表示以用于检索相关文章："` 提升检索意图对齐
- **三级继承检索**：店铺层 → 品牌层 → 通用层，按优先级排序；品牌隔离过滤 + 禁用语过滤 + store_id权限过滤
- **知识库结构**：通用层(80%)全矩阵共享，品牌层(15%)按品牌隔离，店铺层(5%)仅存差异项

### 5. LLM 工程

**三层结构化输出保障：**

```
第一层-主动预防: response_format=json_object + temperature=0.2 + Prompt显式声明Schema
第二层-被动检测: JSON解析→5项字段完整性校验→step3≥20字→核心话术缺失整条作废切模型
第三层-降级兜底: 部分缺失标灰展示 / 完全失败降级纯文本 / 失败case全部落库驱动Prompt迭代
```

**模型降级链**：DeepSeek V4 Flash → Qwen3.5 Plus → Hunyuan Hy3，按`.env`中`LLM_FALLBACK_ORDER`可配置。11模型选型评测（4维度×加权评分矩阵），实测test_prompt.py验证结构化输出可靠性——DeepSeek-V4-Pro/Flash达100% JSON可解析率，V3.2和混元为0%。

**级联重生成**：修改五步中任一步→locked_steps原样保留→LLM仅生成下游步骤→Merge返回完整五步。RAG缓存复用（消息metadata反序列化），避免重复向量检索。

**上下文分层管理**：近15轮原文 + 15-30轮增量笔记 + 30轮以上一句总结，防止LLM长对话"Lost in the Middle"退化。

### 6. 数据飞轮

客服收藏话术 → 自动打品牌标签 → 进入微调初筛数据集。三种零摩擦反馈路径：⭐收藏 / 评估报告底部一键标注 / AI失败后引导录入。每条对话同时记录AI生成版(agent)和人类实际发送版(customer)，差异即人类偏好信号，积累足够多用于后续RLHF/DPO训练专属客服模型。

### 7. 评估与监控

- **个人评估报告**：意图准确度+话术质量+修改率+收藏率 + 团队均值对比 + 7天趋势 + LLM生成改进建议
- **知识缺失自发现**：RAG Top-1<0.7 + LLM knowledge_sufficient=false 双重触发 → 同义query语义聚类 → 同一cluster≥5次推送管理后台审核
- **店铺趋势感知**：突增检测（今日>7日均值×2）和持续高位（本周>4周均值×1.5）两种预警模式

## 三、关键架构决策

| 决策       | 选择                     | 理由                                                        |
| ---------- | ------------------------ | ----------------------------------------------------------- |
| Agent架构  | Orchestrator（非ReAct）  | 客服场景核心是知识检索而非多步推理；ReAct延迟高             |
| 知识库组织 | 通用→品牌→店铺三级继承 | 代运营跨品牌/跨平台，知识必须隔离；继承+覆盖减少配置        |
| 结构化输出 | 五步JSON协议             | 短期质量管控，长期数据标注流水线（Agent换，协议不变）       |
| 检索方案   | 自实现BM25+pgvector混合  | 精确关键词+语义泛化互补，不引入新数据库                     |
| 多模态     | CLIP+多模态LLM双路并行   | CLIP精确匹配商品，多模态LLM理解场景图片；双向量空间独立检索 |
| 权限隔离   | JWT store_ids + RAG过滤  | 单客服仅搜授权店铺（~6000条/0.3%总量），管理员无限制        |
| 上下文管理 | 15/30轮分层截断          | 近15轮原文+15-30轮增量笔记+30轮+一句总结                    |

## 四、数据库（11张核心表）

users / brands / stores / conversations / messages / collections / knowledge_vectors(HNSW) / product_images(HNSW) / intent_labels / knowledge_gaps / trend_alerts

关键设计：无FK约束、config用JSONB灵活扩展、metadata JSONB承载多用途（RAG溯源+缓存）、双向量空间（文本1024维+图片768维，各自独立HNSW索引）

## 五、项目亮点

**Agent 架构评测决策**：跑单Agent vs Orchestrator对比评测，引用ASA论文支撑，设明确决策门槛（Tool准确率<80%降级）

**结构化输出三层保障**：JSON Mode预防→5项校验检测→降级兜底不阻断→失败case落库驱动Prompt迭代，形成闭环

**11模型选型方法论**：4维度×加权评分矩阵 + 实测数据验证（test_prompt.py），每个结论可量化回溯

**自实现中文BM25混合检索**：bigram分词 + BM25(k1=1.2,b=0.75) + pgvector余弦 + 层级加权 + 品牌禁用语过滤

**五步生成法 = 数据协议**：短期QC工具，长期数据标注流水线。AI生成版 vs 人类采纳版的差异 = 偏好信号

**多模态输入统一路由**：文字/图片(CLIP+多模态LLM双路)/视频(关键帧+OCR+ASR)/链接四通道统一入口，双向量空间独立检索

**知识充分性自判**：LLM生成话术同时输出knowledge_sufficient，零额外调用成本，与RAG分数形成双重触发

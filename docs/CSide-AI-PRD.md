## 1 需求背景

代运营客服每天面对的是多品牌、多平台、多店铺并行的服务场景，回复质量高度依赖个人经验。资深客服能凭经验判断客户诉求、把握政策边界，并在对话中顺势推动下单；新人往往要反复确认口径，容易出现两类偏差：一类是答错，做出超出政策的承诺；另一类是答完即止，把问题解释清楚后就此结束，没有推动客户进入下一步。前者带来合规与售后风险，后者直接造成成交流失。

从业务价值看，售前咨询中的客户多数已经具备购买意愿，缺少的往往只是临门一脚的推动。传统客服话术体系通常只覆盖"回答问题"这一层，既缺少对客户所处阶段的判断，也缺少促成动作，这正是咨询量很大而成交率上不去的主要原因。

引入大语言模型承接这部分工作，难点并不在于"能不能写出通顺的话术"，而在于三点：模型会不会用错知识、会不会遗漏促成环节、效果能否被持续度量。客服场景对准确性的要求高于一般写作类场景，退货政策、保修范围、活动规则都有明确边界，一旦答错即构成业务事故；同时，一次合格的回复不仅要答对，还要完成推动。

本产品的应对方式是：把一次客服沟通拆解为意图识别、回复策略、推荐话术、钩子引导、成功收尾五个环节，即五步生成法，由 AI 逐环节给出建议，使促成动作从"可做可不做"变为每次生成都必须给出的必答项。围绕这一核心能力，产品同时提供两项支撑：

- 知识支撑：让每句建议都有商品信息与政策条款作为事实依据，并保证只使用当前店铺的私有知识；
- 上下文支撑：保证 AI 知道此刻服务的是哪个品牌、哪个平台、哪个店铺。

本文档定义上述能力的需求内容，包括五步生成的结构与输出契约、支撑其准确性的检索与上下文机制、异常情况下的降级方式，以及效果度量指标与验收标准。业务背景、行业痛点与产品定位见《CSide 电商代运营 AI 客服助手 产品方案》第 2 章与第 3 章。

## 2 目标与非目标

### 2.1 目标

产品目标分为业务目标与产品目标两层。业务目标回答"为业务带来什么"，产品目标回答"AI 能力必须达到什么状态才能支撑业务目标"。

表 2-1 目标

| 编号 | 层面 | 目标 |
|---|---|---|
| G1 | 业务 | 拉平客服之间的能力差距，使新人在同等场景下产出接近资深人员的回复 |
| G2 | 业务 | 提升售前咨询下单率，通过每次生成必答的引导环节，减少咨询后未下单的流失 |
| G3 | 业务 | 缩短单条回复的编写时间，减少咨询高峰期的响应压力 |
| G4 | 业务 | 杜绝跨店、跨品牌的政策错配，避免由此产生的错误承诺与售后纠纷 |
| G5 | 产品 | 生成结果五步完整、字段齐全，可直接支撑复制、收藏与统计 |
| G6 | 产品 | 生成内容不包含品牌禁用语，检索结果不包含其他品牌的私有知识 |
| G7 | 产品 | 生成延迟满足客服实时使用要求 |
| G8 | 产品 | 品牌与店铺配置修改后即时生效，无需重启服务或重新导入知识 |
| G9 | 数据 | 沉淀带标签的分步内容与失败样本，为知识补充与后续模型优化提供素材 |

### 2.2 非目标

表 2-2 非目标

| 编号 | 非目标 | 说明 |
|---|---|---|

| N6 | 本期不引入重排序模型与新向量数据库 | 关键词与向量混合检索已可满足准确性要求，避免增加运维复杂度 |

| US-7 | 一线客服 | 我希望在上下文不完整时无法发起生成，避免把建议错发到其他店铺 | 品牌、平台、店铺任一未确认时，生成入口不可用并给出提示 |
| US-8 | 一线客服 | 我希望切换店铺后不残留上一家店的消息与结果 | 切换上下文时清空客户消息、生成结果、收藏状态与会话标识 |
| US-9 | 一线客服 | 我希望能抓取页面上选中的客户消息，不必手动复制 | 支持通过快捷键抓取页面选中文本，抓取失败时给出明确提示 |
| US-10 | 一线客服 | 我希望把好用的分步内容收藏下来，之后还能找到 | 五步中任一步均可收藏，收藏后带品牌、平台与场景标签，并可按条件查询 |
| US-11 | 一线客服 | 我希望生成失败时能快速重试，而不是从头再来 | 失败时保留原输入并提供重试入口，给出可理解的失败原因 |
| US-12 | 运营管理员 | 我希望修改品牌话术风格或禁用语后，客服下一次生成就生效 | 配置保存后无需重启服务与重新导入知识，后续生成立即体现变更 |
| US-13 | 运营管理员 | 我希望维护店铺的活动与特殊规则，使其体现在回复中 | 店铺配置保存后可被检索并经生成进入建议 |
| US-14 | 业务负责人 | 我希望团队优质话术沉淀下来，不因人员流动而流失 | 收藏数据带标签留存，并按步骤进入对应资产用途 |
| US-15 | 业务负责人 | 我希望能够判断这套工具是否真的提升了转化 | 可获取过程指标数据；订单数据打通后可获取售前咨询下单率 |

## 4 功能结构

AI 能力以五步生成法为核心，另有三条支撑线保证其准确与可用。四条线构成一条完整链路，任一环节失效都会直接反映为答复错误或转化流失，因此不可单独评估。

图 4-1 能力结构

```
核心能力 五步生成法
  意图识别 → 回复策略 → 推荐话术 → 钩子引导 → 成功收尾

支撑线一 上下文正确
  平台与品牌识别、上下文确认、生成门禁、结果一致性校验

支撑线二 知识正确
  三级知识体系、混合检索、品牌隔离、禁用语过滤

支撑线三 闭环沉淀
  知识溯源展示、分步收藏、品牌与店铺配置、效果度量
```

表 4-1 能力线与对应模块

| 能力线 | 模块 | 职责 |
|---|---|---|
| 核心能力 | 五步生成模块 | 按五步结构生成建议，输出可逐项校验的结果 |
| 上下文正确 | 上下文识别模块 | 依据域名、地址参数与页面标题识别品牌、平台与店铺 |
| 上下文正确 | 生成门禁模块 | 校验上下文完整性，控制生成入口的可用性 |
| 上下文正确 | 一致性校验模块 | 生成返回后比对上下文，不一致则不予展示 |
| 知识正确 | 查询处理模块 | 为查询文本附加检索指令，生成查询向量 |
| 知识正确 | 候选召回模块 | 按层级、品牌与平台条件召回候选并按相似度排序 |
| 知识正确 | 安全过滤模块 | 执行品牌隔离二次校验与禁用语过滤 |
| 知识正确 | 融合排序模块 | 融合关键词与向量分值，叠加层级加权，截取前 5 条 |
| 闭环沉淀 | 结果输出模块 | 展示五步结果与知识溯源，支持复制与分步收藏 |
| 闭环沉淀 | 配置管理模块 | 管理品牌与店铺配置，配置变更即时生效 |
| 闭环沉淀 | 度量模块 | 采集并统计各环节指标 |

## 5 详细设计

### 5.1 五步生成法（核心能力）

#### 5.1.1 五步定义与转化作用

五步生成法的设计出发点，是让模型在生成时不能只回答问题，还必须完成对客户所处阶段的判断与对下一步动作的推动。

表 5-1 五步定义与转化作用

| 步骤 | 名称 | 产出内容 | 在转化中的作用 | 缺失后的后果 |
|---|---|---|---|---|
| 第一步 | 意图识别 | 客户意图、所处决策阶段与情绪判断 | 判断客户当前处在信息了解、方案比较、异议处理还是决策临门阶段 | 策略与客户实际阶段错配，答非所问 |
| 第二步 | 回复策略 | 本次沟通的解决路径与说服方式 | 决定采用信息解答、价值锚定、异议化解还是临门推动 | 回答千篇一律，无法化解具体顾虑 |
| 第三步 | 推荐话术 | 客服可直接复制发送的完整话术 | 承载说服内容，是客户实际看到的信息 | 客服仍需自行组织语言，效率与质量不稳定 |
| 第四步 | 钩子引导 | 引导客户进入下一步动作的建议 | **转化发生的关键环节**，推动客户下单、加购、领券或查看详情 | 客户停留在咨询阶段，咨询结束后即流失 |
| 第五步 | 成功收尾 | 结束语与后续铺垫 | 关闭本次沟通，为复购与后续触达留出接口 | 对话生硬结束，缺少后续机会 |

#### 5.1.2 客户决策阶段与五步的映射

图 5-1 客户决策路径与五步的映射

```
客户决策路径                    五步生成法的对应产出

信息了解 ─┐
方案比较 ─┼─▶ 第一步 意图识别：判断所处阶段、情绪与隐藏需求
异议处理 ─┤
决策临门 ─┘
                    │
                    ▼
             第二步 回复策略：匹配该阶段的说服路径
                    │
                    ▼
             第三步 推荐话术：输出可发送的说服内容
                    │
                    ▼
             第四步 钩子引导：推动进入下单等下一步动作  ◀── 转化关键点
                    │
                    ▼
             第五步 成功收尾：关闭本次沟通并铺垫复购
```

#### 5.1.3 输出契约与模型参数

表 5-2 输出字段与校验要求

| 字段 | 含义 | 最小长度 |
|---|---|---|
| 意图识别 | 客户意图与情绪分析 | 10 字 |
| 回复策略 | 回复策略与逻辑 | 10 字 |
| 推荐话术 | 可直接发送的话术内容 | 20 字 |
| 钩子引导 | 引导客户下一步行动 | 5 字 |
| 成功收尾 | 结束语与后续铺垫 | 5 字 |

推荐话术字段用于发送，校验要求最高；意图识别与回复策略决定后续两步的质量，同样设置了下限；钩子引导与成功收尾为短句，长度要求相应放宽。

表 5-3 生成参数

| 参数 | 取值 | 取值依据 |
|---|---|---|
| 响应格式 | 结构化对象 | 在协议层要求结构化输出，降低解析失败概率 |
| 采样温度 | 0.2 | 客服话术需稳定可复现，低温可降低措辞漂移与内容编造 |
| 最大输出长度 | 1200 | 五步内容合计约 400 至 700 字，该值留有充分余量并可抑制无效长输出 |
| 请求超时 | 45 秒 | 主流模型实际耗时 3 至 12 秒，个别模型超过 40 秒，该值兼顾成功率与等待体验 |
| 连接超时 | 10 秒 | 快速识别网络不可达场景，避免无效等待 |
| 降级顺序 | DeepSeek、通义千问、腾讯混元 | 评测显示三者结构化输出可解析率均为 100%，按成本与速度梯度配置冗余 |
| 输入长度上限 | 500 字符 | 覆盖绝大多数客户消息，超长内容属异常输入，先行拦截 |

#### 5.1.4 结构化输出的三层保障

结构化输出是五步协议得以落地的前提。产品在生成、校验与降级三个环节分别设置约束，使输出质量在不同模型之间保持一致且可预期。

图 5-2 结构化输出的三层保障

```
第一层 主动预防
  调用时启用结构化输出约束；在提示词中显式声明字段与长度要求

第二层 被动检测
  解析校验 → 字段完整性校验 → 内容长度校验 → 类型校验
  失败时切换备用模型重新生成

第三层 降级兜底
  部分缺失：缺失字段单独标识，其余字段正常可用
  完全失败：降级为纯文本展示，保证对话不被阻断
  全程记录：校验失败的原始输出完整留存，用于提示词与模型优化
```

表 5-4 校验规则与处理方式

| 校验项 | 规则 | 失败处理 |
|---|---|---|
| 结构可解析 | 返回内容可被解析为结构化对象 | 重新生成一次；仍失败则切换备用模型 |
| 意图识别 | 字段非空且不少于 10 字 | 该字段单独标识，其余字段正常展示 |
| 回复策略 | 字段非空且不少于 10 字 | 同上一行 |
| 推荐话术 | 字段非空且不少于 20 字 | 核心字段缺失，整条结果作废并切换模型重新生成 |
| 钩子引导 | 字段非空且不少于 5 字 | 该字段单独标识，不影响推荐话术使用 |
| 成功收尾 | 字段非空且不少于 5 字 | 同上一行 |

推荐话术是唯一被直接发送的字段，因此采用最严格的处理方式；其余字段即使缺失也不会阻断客服使用，但会在界面上明确标识，避免客服误以为内容完整。

### 5.2 知识检索（支撑能力）

检索决定模型能看到什么，是准确性的基础。客服问题的表述高度口语化，例如客户说"拍小孩""耳机一边没声"，而知识库中的标准表述是"运动抓拍""单边无声"，字面几乎没有重合；同时又有大量精确的专有词，例如型号、保修期限、退换时限。单一检索方式无法同时覆盖这两类情况，因此采用关键词检索与向量检索融合的方案。

知识按通用、品牌、店铺三级组织。通用层沉淀全矩阵共用的标准话术与平台政策，品牌层承载品牌差异，店铺层仅存放店铺特有的活动与规则。检索时三级同时参与，并按业务优先级排序：店铺差异优先于品牌差异，品牌差异优先于通用内容。

为避免代运营场景下最严重的串品牌问题，检索在数据过滤之外，还执行一次品牌归属校验，非通用层的知识必须与请求品牌一致；同时按品牌配置的禁用语清单过滤知识内容。

表 5-5 检索参数

| 参数 | 取值 | 取值依据 |
|---|---|---|
| 候选集上限 | 200 | 在保证召回覆盖率的前提下控制关键词计算量 |
| 结果条数 | 5 | 提示词容量有限，5 条约 500 字；继续增加会稀释关键知识并提高调用成本 |
| 关键词权重 | 0.75 | 客服问题包含大量确定型号与政策关键词，精确匹配的可靠性高于语义泛化 |
| 向量权重 | 0.20 | 承担同义与口语化表达的泛化职责，作为关键词检索的补充 |
| 层级加权 | 店铺 +0.05，品牌 +0.03，通用 0 | 对应三级知识的业务优先级；加权幅度小于分项权重，仅用于同分或近似分时判定次序，不使其压过内容相关性 |
| 关键词算法参数 | k1 取 1.2，b 取 0.75 | 分别为词频饱和系数与文档长度归一化系数，采用成熟默认值，避免无数据支撑的调参 |
| 中文分词策略 | 汉字按单字与双字组合切分，英文与数字按连续片段切分 | 不引入外部分词组件，实现可解释且无额外依赖；双字组合可覆盖口语片段 |
| 查询指令前缀 | 为这个句子生成表示以用于检索相关文章 | 该向量模型在非对称检索场景下的推荐用法，可提升查询与文档的意图对齐 |
| 向量维度 | 1024 | 与本地模型原生维度一致；云端替代方案采用相同维度，两套实现共用同一列，可切换但不可混用 |
| 向量索引 | HNSW，余弦距离 | 近似最近邻检索避免全表扫描，余弦距离与归一化相似度语义一致 |

### 5.3 上下文识别与生成门禁（支撑能力）

客服同时负责多个店铺，上下文识别一旦出错，后续检索与生成都建立在错误前提之上，因此该模块是整条链路的前置条件。

自动识别存在固有局限：部分电商后台在切换店铺时只更新页面标题而不改变地址，各平台的店铺标识命名也不统一。因此产品采用"自动识别给出候选、人工确认后方可使用"的策略：自动识别结果仅作提示，确认状态保持为未确认；由客服手动选择后，来源标记为手动并保持优先，不再被同页的自动识别结果覆盖。

表 5-6 上下文识别与门禁设计

| 设计项 | 取值 | 取值依据 |
|---|---|---|
| 平台识别依据 | 域名后缀匹配，覆盖天猫、拼多多别名域与抖店域名 | 域名不受单页应用路由影响，稳定性最高 |
| 品牌识别依据 | 地址查询参数与页面标题正则匹配 | 平台未提供统一店铺字段，需多信号兜底；页面标题是切换店铺时少数会变化的信号 |
| 变化监听方式 | 监听地址与标题变化，并设置 1 秒定时轮询 | 平台事件不完整，轮询用于兜底；1 秒为及时性与资源开销之间的折中 |
| 状态存储方式 | 按标签页隔离的会话级存储 | 支持多店并行且互不干扰；会话级不落盘，符合隐私预期 |
| 上下文优先级 | 人工选择高于自动识别 | 人工判断的可靠性高于启发式识别 |
| 生成门禁条件 | 品牌、平台、店铺均已确认方可发起生成 | 未确认即生成是跨店错配的主要成因，宁可增加一次确认操作 |
| 切换处理 | 切换上下文时清空消息、结果、收藏状态与会话标识 | 避免旧上下文数据写入新上下文，同时使进行中的历史请求失效 |

### 5.4 分步收藏与数据沉淀（支撑能力）

生成结果本身不构成闭环，还需要让客服能够判断、采纳与沉淀，让运营能够持续校正。

客服侧展示本次引用的前 3 条知识及其层级、类型、场景与匹配度。这一设计的价值在于把判断权交还客服：当引用来源与客户问题明显不符时，客服可以主动放弃使用该建议，而不是盲目复制。

收藏环节把客服的认可行为转化为带标签的结构化数据。收藏时系统自动从当前会话反查品牌、平台与店铺，客服无需手工填写；收藏内容同时保留触发收藏时的客户消息，便于后续构造问答样本。五步的每一步收藏后进入不同用途，其中引导模板库直接服务转化。

表 5-7 分步收藏去向

| 收藏的步骤 | 沉淀分类 | 后续用途 |
|---|---|---|
| 第一步 意图识别 | 意图案例库 | 用于验证与补充意图识别评测集 |
| 第二步 回复策略 | 策略模式库 | 按场景与意图分类，遇到同类场景可直接复用策略逻辑 |
| 第三步 推荐话术 | 话术模板库 | 可直接复用的话术；高频内容可进入检索候选池 |
| 第四步 钩子引导 | 引导模板库 | 按平台与场景分类，跨对话复用，直接服务转化 |
| 第五步 成功收尾 | 收尾模板库 | 按场景分类复用 |

配置环节解决的是"生成结果会漂移，但业务口径不能漂移"的问题。品牌的话术风格、禁用语清单、退货政策与保修条款由运营在后台维护，修改后同时作用于两个位置：提示词中的输出约束，以及检索阶段的禁用语过滤。一次修改、两处生效，无需重启服务，也无需重新导入知识。

## 6 异常与兜底

AI 能力的失败模式与传统功能不同：除了接口报错，还包括"接口正常但结果不可用"。因此兜底设计需覆盖参数非法、服务异常、结果不完整与结果越界四类情况。

表 6-1 异常场景与处理方式

| 环节 | 异常场景 | 处理方式 |
|---|---|---|
| 上下文 | 页面不属于受支持的电商平台 | 上下文保持未识别状态，提示客服手动选择 |
| 上下文 | 快捷键抓取选中文本失败 | 提示当前页面不支持读取选中文本，引导手动输入 |
| 上下文 | 标签页关闭 | 清理该标签页状态，避免客户文本残留 |
| 上下文 | 上下文未确认 | 不开放生成入口并给出提示 |
| 检索 | 候选集为空 | 按无可用知识处理，同时记录知识缺口信号 |
| 检索 | 品牌过滤后候选全部被排除 | 返回空结果并触发告警，通常指示知识未导入或品牌名称不一致 |
| 检索 | 向量服务不可用 | 降级为仅关键词检索，不得中断生成 |
| 检索 | 检索超时 | 设置独立超时，超时按无知识处理，不拖累整体链路 |
| 生成 | 客户消息为空或超过长度上限 | 客户端拦截并提示，服务端返回对应错误码 |
| 生成 | 品牌不存在 | 返回业务错误码，引导客服重新选择店铺 |
| 生成 | 单一模型调用失败或返回无效内容 | 自动切换下一节点，并记录失败原因 |
| 生成 | 全部模型调用失败 | 返回服务错误码，提示稍后重试 |
| 生成 | 结构无法解析或推荐话术缺失 | 整条结果作废并切换模型重新生成 |
| 生成 | 非核心字段缺失 | 在界面单独标识该字段，其余内容正常可用 |
| 生成 | 检索结果为空 | 生成时限定为仅依据品牌与平台政策作答，不得虚构优惠信息 |
| 结果 | 返回结果与请求上下文不一致 | 不予展示并提示重试 |
| 结果 | 响应延迟过大 | 展示生成中状态，超时后给出明确提示并保留原输入供重试 |

## 7 数据埋点与指标

AI 能力的迭代必须以数据为依据，因此埋点不是可选功能，而是需求的一部分。指标分为结果、过程、质量、效率四层：过程层用于定位损耗环节，结果层用于衡量对转化的贡献。

表 7-1 埋点与指标

| 类别 | 指标 | 计算方式 | 目标 |
|---|---|---|---|
| 结果 | 售前咨询下单率 | 产生下单行为的售前咨询会话数与售前咨询会话总数之比 | 相较基线提升 |
| 结果 | 咨询到下单转化率 | 售前咨询会话中完成下单的比例，按品牌与店铺拆分 | 相较基线提升 |
| 过程 | 五步生成采纳率 | 复制推荐话术次数与生成成功次数之比 | 建立基线并持续提升 |
| 过程 | 引导执行率 | 客服保留并执行钩子引导的比例 | 建立基线 |
| 过程 | 五步完整率 | 返回结果中五步字段均满足长度要求的比例 | 不低于 95% |
| 过程 | 分步收藏量 | 各步骤内容的累计收藏条数 | 建立基线 |
| 过程 | 自动识别成功率 | 自动识别出有效上下文的比例 | 不低于 95% |
| 稳定性 | 生成成功率 | 成功响应数与总请求数之比 | 不低于 98% |
| 稳定性 | 结构化输出一次通过率 | 首个模型即通过校验的请求占比 | 不低于 95% |
| 稳定性 | 降级发生率 | 触发模型切换的请求占比 | 不高于 5% |
| 质量 | 禁用语命中率 | 生成文本包含品牌禁用语的请求占比 | 0，为强制要求 |
| 质量 | 跨品牌知识返回数 | 检索结果中品牌与请求品牌不一致的条数 | 0，为强制要求 |
| 质量 | 知识空召回率 | 检索结果为空的比例 | 不高于 5% |
| 质量 | 店铺层知识召回率 | 检索结果中包含店铺层知识的请求占比 | 不低于 30% |
| 质量 | 首条知识分值分布 | 每次检索首条结果的分值 | 用于识别知识缺口 |
| 性能 | 生成延迟 | 请求发起到响应返回，统计 P50 与 P95 | P50 不高于 6 秒，P95 不高于 20 秒 |
| 性能 | 检索延迟 | 检索模块耗时，统计 P95 | 不高于 300 毫秒 |

结果层指标依赖订单数据与会话数据的关联，在订单数据完成接入后启用；在此之前，以过程层与质量层指标衡量能力的使用深度与准确性。

## 8 验收标准

AI 能力的效果具有概率性，仅验证功能是否实现不足以说明可用，因此验收分为功能、效果、性能与业务四类，须同时通过方可判定达标。

表 8-1 验收标准

| 类型 | 验收内容 | 标准 |
|---|---|---|
| 功能验收 | 五步生成的完整性与输入校验 | 端到端可用，五步字段齐备，输入校验与错误码符合契约 |
| 功能验收 | 降级与兜底机制 | 断开主模型后可自动切换；向量服务异常时可降级；结构异常时可整条重生成或分字段标识 |
| 功能验收 | 上下文门禁 | 上下文未确认时无法发起生成；一致性问题可被识别并拦截 |
| 功能验收 | 收藏与配置 | 收藏自动标注正确；配置修改后无需重启即可生效 |
| 效果验收 | 输出完整性 | 依据评测集回归，五步完整率为 100% |
| 效果验收 | 合规红线 | 品牌禁用语命中数为 0；跨品牌知识返回数为 0 |
| 效果验收 | 检索质量 | 知识空召回率不高于 5%；店铺层知识可被召回 |
| 性能验收 | 生成与检索延迟 | 生成 P95 不高于 20 秒；检索 P95 不高于 300 毫秒 |
| 业务验收 | 使用效果 | 生成采纳率与收藏率达到基线；引导内容被保留使用的比例达到基线 |
| 业务验收 | 转化效果 | 订单数据打通后，灰度范围内的售前咨询下单率不低于对照范围 |
| 业务验收 | 风险控制 | 因生成建议导致的口径类投诉不上升 |

业务验收中的风险控制项属于一票否决：若口径类投诉上升，即使其他指标达标，也不得扩大灰度范围。

## 9 上线与迭代

AI 能力的效果受知识内容、提示词与模型版本共同影响，任一变更都可能改变全部输出，因此发布策略与迭代机制需要与之匹配。

表 9-1 上线与迭代要求

| 环节 | 要求 |
|---|---|
| 发布方式 | 通过配置开关控制；先以影子模式运行，再按 5% 至 20% 灰度，最后全量 |
| 发布判据 | 影子运行期间，新版本的生成采纳率、五步完整率与禁用语命中率不低于旧版本 |
| 回滚机制 | 保留上一版本的提示词模板、检索参数与模型配置，异常时可在数分钟内切回 |
| 观测周期 | 灰度阶段每日观察质量与性能指标，确认无异常后扩大范围 |
| 转化观测 | 订单数据打通后，灰度与对照范围按同口径对比售前咨询下单率 |
| 迭代来源 | 以失败样本、低分知识记录与未被保留的引导内容为输入，优先补齐知识，其次调整提示词 |
| 迭代节奏 | 提示词与知识按月迭代；模型选型按季度复评，兼顾准确率、延迟与成本 |
| 回归要求 | 每次涉及提示词、检索参数或模型的变更，须重跑评测集并核对效果指标 |
